# 採否と再発防止

検討時に該当行だけ読む。状態は2026-09-14時点。数値・対象DLL・出典識別子は[台帳](evidence.json)。
現行5機能の寄与は`runtime-feature-ranking-20260914`。通常FPSと高速TPSを分けた機能別OFF比較であり、寄与率を足し合わせない。
旧版内部の47回比較は`legacy-feature-attribution-20260914`、版間差の追加20回比較は`version-gap-interaction-20260914`。
結果の要約は[引継ぎ](HANDOFF.md)。機能群へのON/OFFの効果を、個々の機能への一意な配分や安全な再導入の根拠にしない。

## 同じ失敗を繰り返さないための判断

## ロードで残す知見

- 有効機能は`LoadPatches.Install`と各互換性検査を読む。初期化通知の配送、構築プラン、
  ナビ/地形等は導入済みであり、古いプロファイルの全費用が今も残っているとは限らない。
- 1.1.2.0→1.1.2.4対応は対象モジュールの差分監査を経たもの。MVIDだけを追加して未知版を許可しない。
  多くのロード最適化が1.0でnative fallbackになるのは想定内。
- GoodStackだけにFrontierの`ComponentCache.Initialize`監視ownerの限定免除を採用。
  同じ免除をPreparedEntityVisualsへ広げた試作では選択レイ32件に差が出たため、こちらはfallbackを保持する。
- 遅延モデルは生成前の構造差だけで不合格/合格にせず、初回使用・生成後のモデル・選択判定を比較する。
  準備時間の短縮を、初回使用へ移した費用やロード全体の短縮と混同しない。
- テンプレートからのadapter複製、非同期clone、建設段階/プレビューの遅延等の試作は、
  現行`LoadPatches`へ入っている機能と区別する。同値性と総ロード時間の両方を満たすまで有効にしない。
- ロードのmain-thread CPU秒とシーン待ち時間は別の指標。入れ子区間を二重加算しない。
  小さい部分最適化を積み上げた倍率や「1秒ロード達成」は主張しない。

## 表示・互換性

| 症状/領域 | 分かったこと、残る限界 |
|---|---|
| 配管の明かりが残る | T3MPなしでも再現した登録残留。建物へ入った直後にTubeVisitorが残る。TubeVisitFixで解除する。移動アニメーションの修正ではない |
| 数フレーム飛ぶようなカクつき | 旧版の報告はある。バニラ単独で同じ症状を再現した証拠は未確認。5秒間隔のModelGapMonitorをフレーム単位の証拠にしない |
| 水/冠水の表示残留 | GPU履歴不整合は再現・対処済み。冠水/排水/再ロードの限定試験もあるが、旧ユーザー報告すべての原因を特定したとは言わない |
| 旧設置/選択UI最適化 | 不採用。再構築の繰り返しで階段描画に到達しない条件、古いノードと現在の入口が混ざる条件を静的確認。モデル更新の遅延はUI外にも作用した |
| 旧FlowField置換 | UI表示と通常の移動探索で共有。UI専用の軽量化として一括再導入しない |
| 階段MOD | Hooman Stairs 2.0.2で両版の接続・解体後グラフ/順序16組一致。設置中の表示、全階段MOD、VerticalNavMeshの実バイナリとの併用を網羅した試験ではない |
| 収穫候補の到達性照会スキップ | v1.2.3で採用（ユーザー指示：効果の有無によらず実装）。寄与せず・非生存・既に圏内フラグ立ちの候補だけ経路照会を省く。先頭候補は必ず照会（フローフィールド充填の副作用維持）。n10c ×50で+0.45％（雑音内）。n10c2で再測定するまで効果を主張しない。台帳`yielder-reachability-skip-20260916` |
| 調査用コードの製品混入 | 禁止を規約と機械ゲートにした（[DIAGNOSTICS](DIAGNOSTICS.md)、`check_product_purity.ps1`）。製品は機能OFFスイッチだけ、検証・プローブ・実験フックはドライバ側。製品の`#if`実験フック28箇所と移動の並走検証を撤去。deploy/verify/measureがゲートを通す。凍結リストのLoading系スイッチは追加禁止 |

新しい報告では、表示上の停止・実際の移動停止・配管照明を分ける。
同じセーブと実効速度で対照を取り、修正したDLLと確認したDLLを結び付ける。

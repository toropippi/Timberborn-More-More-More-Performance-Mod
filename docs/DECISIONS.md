# 採否と再発防止

検討時に該当行だけ読む。状態は2026-09-13時点。数値・対象DLL・出典識別子は[台帳](evidence.json)。

## 同じ失敗を繰り返さないための判断

| 対象 | 判断と再検討の条件 |
|---|---|
| フレーム単位の仕事なし/在庫距離/地区集計キャッシュ | 不採用。1フレームに複数tick進むため状態が陳腐化する。候補の状態は問い合わせ時に読む |
| ワールドをまたぐstaticキャッシュ | 不採用。再ロード・破棄・再登録の境界を対象に含める |
| EventBus delegate化 | 採用。元の登録・検証・呼出順と例外ラップを保持する。メソッド全体の置換へ戻さない |
| 水テクスチャの同一byteアップロード省略 | 採用、D3D11限定。他パッチによるnative実行を挟むとGPU履歴が古くなるため、Harmony再生成時の履歴破棄を維持する |
| Frontier | 採用。無効tickableだけの空の訪問を省く。Enable/Disable/Initialize/Destroyの追跡とnative Tickのガードを維持する |
| Frontierの一致キー検索短縮 | ソースで試作済み。既定比較器で現在位置と一致すれば再検索を省く。他の比較器は従来の呼出を維持。単体試験は一致、ゲーム全体での純増は未測定 |
| TickEntityFastのindex走査 | 削除済み。Frontier有効時の単独効果を確認できなかった。原版は構造体列挙子であり「indexの方が速い」と仮定しない |
| Frontier位置索引の追加 | 保留。再測定も外部計算と重なり、隣接比較の優劣が反転。安定した純増が再検討条件 |
| 道路探索結果の再利用 | 保留。同じ観測フック同士の差と、製品への純増が一致しない。建設/解体時の破棄・他MOD互換性も未完 |
| 移動のベクトル長計算再利用 | 不採用。同値性の検査後のn10c比較で実用的な寄与を確認できなかった |
| Unity生存判定の事前DLL書換え | 不採用。n10cの増益が一貫せず、Workshop MODへの移植方法も別問題。T4MPのJIT条件をそのまま当てはめない |
| 運搬先Sortの前回結果再利用 | 低優先。実測の一致部分は約64秒中4.9ms。候補生成を含むinclusive時間をSortの削減可能量にしない |
| 収穫/植林の状態キャッシュ | 低優先。観測寄与が小さく、Enable/Disable等で収穫量イベントが出ない経路がある。距離二乗化やソートも丸め・同順位・呼出順を変える |
| BehaviorManagerの外側ループ置換 | 不採用。内側の行動処理の費用をループ自身の削減余地と誤認しない。列挙変更検出・途中のMetrics切替・例外後の再実行に注意 |
| WaterObjectの追加最適化 | 未採用。基準座標の保持・水位不変時の通知省略は原版にもある。現在の状態を読まない旧独自キャッシュへ戻さない |

## ロードで残す知見

- 有効機能は`LoadPatches.Install`と各互換性検査を読む。初期化通知の配送、構築プラン、
  ナビ/地形等は導入済みであり、古いプロファイルの全費用が今も残っているとは限らない。
- 1.1.2.0→1.1.2.4対応は対象モジュールの差分監査を経たもの。MVIDだけを追加して未知版を許可しない。
  多くのロード最適化が1.0でnative fallbackになるのは想定内。
- GoodStackだけにFrontierの`ComponentCache.Initialize`監視ownerの限定免除を採用。
  同じ免除をPreparedEntityVisualsへ広げた試作では選択レイ32件に差が出たため、こちらはfallbackを保持する。
- 遅延モデルは生成前の構造差だけで不合格/合格にせず、初回使用・生成後のモデル・選択判定を比較する。
  準備時間の短縮を、初回使用へ移した費用やロード全体の短縮と混同しない。
- テンプレートからのadapter複製、非同期clone、建設段階/プレビューの遅延等の試作は、
  現行`LoadPatches`へ入っている機能と区別する。同値性と総ロード時間の両方を満たすまで有効にしない。
- ロードのmain-thread CPU秒とシーン待ち時間は別の指標。入れ子区間を二重加算しない。
  小さい部分最適化を積み上げた倍率や「1秒ロード達成」は主張しない。

## 表示・互換性

| 症状/領域 | 分かったこと、残る限界 |
|---|---|
| 配管の明かりが残る | T3MPなしでも再現した登録残留。建物へ入った直後にTubeVisitorが残る。TubeVisitFixで解除する。移動アニメーションの修正ではない |
| 数フレーム飛ぶようなカクつき | 旧版の報告はある。バニラ単独で同じ症状を再現した証拠は未確認。5秒間隔のModelGapMonitorをフレーム単位の証拠にしない |
| 水/冠水の表示残留 | GPU履歴不整合は再現・対処済み。冠水/排水/再ロードの限定試験もあるが、旧ユーザー報告すべての原因を特定したとは言わない |
| 旧設置/選択UI最適化 | 不採用。再構築の繰り返しで階段描画に到達しない条件、古いノードと現在の入口が混ざる条件を静的確認。モデル更新の遅延はUI外にも作用した |
| 旧FlowField置換 | UI表示と通常の移動探索で共有。UI専用の軽量化として一括再導入しない |
| 階段MOD | Hooman Stairs 2.0.2で両版の接続・解体後グラフ/順序16組一致。設置中の表示、全階段MOD、VerticalNavMeshの実バイナリとの併用を網羅した試験ではない |

新しい報告では、表示上の停止・実際の移動停止・配管照明を分ける。
同じセーブと実効速度で対照を取り、修正したDLLと確認したDLLを結び付ける。
